Evidence-Grounded Market Agent

Design sample — retrieve → calculate (reproducibly) → combine cross-dataset evidence → answer with calibrated confidence. Built for the easy/medium/hard, single- & cross-dataset benchmark.

LangGraph Local NIM LLM Deterministic math Calibrated JSON output

1 · The four requirements → four components

R1 — RETRIEVE

Dataset Router + Retrievers

A planner decomposes the question and picks which dataset(s) to query (rates, stocks, …). Every retrieved record keeps a source tag: rates.json#2026-05-12.

R2 — CALCULATE

Deterministic Calculator Tool

The LLM never does arithmetic. All math (Δ%, mean, correlation, CAGR) runs in Python with fixed rounding — same question, same number, every run. Each calculation is logged: inputs → operation → result.

R3 — COMBINE

Evidence Ledger (graph state)

Sub-answers from each dataset accumulate in a shared evidence[] list. Cross-dataset questions join on dates/entities in code, then the LLM synthesizes over the joined evidence only.

R4 — ANSWER

Calibrated Structured Output

Final node emits fixed JSON: answer + evidence citations + confidence. Confidence is computed from evidence coverage & agreement, not vibes — and the agent abstains when coverage is low.

2 · LangGraph workflow

Two lanes after the router: calculation questions take the structured-lookup + deterministic-math lane; semantic questions ("why", "describe", "compare in words") take the vector-search lane; hybrid questions run both, and combine merges all evidence. The ground → plan loop retries on gaps; the retry cap guarantees termination.

3 · State & I/O contract

class State(TypedDict):
    question: str
    plan: list[dict]          # [{dataset, sub_query}, ...]
    evidence: list[dict]      # [{source, record, note}, ...]
    calculations: list[dict]  # [{op, inputs, result}]  ← the reproducibility log
    draft: str
    grounded: bool
    retries: int

Output schema (every answer, benchmark-ready):

{
  "answer": "RBA cash rate rose 0.25pp while ASX bank stocks gained 3.1% over the same window.",

4 · Key node implementations

Calculator — reproducible by construction

import statistics

OPS = {
    "pct_change": lambda a, b: round((b - a) / a * 100, 2),
    "mean":       lambda *xs: round(statistics.mean(xs), 4),
    "correlation":lambda xs, ys: round(statistics.correlation(xs, ys), 3),
}

def calculate(state):
    calcs = []
    for step in plan_math_steps(state["plan"], state["evidence"]):
        result = OPS[step["op"]](*step["inputs"])
        calcs.append({**step, "result": result})   # log inputs + op + result
    return {"calculations": calcs}

Cross-dataset combine — join in code, synthesize with LLM

def combine(state):
    # deterministic join, e.g. align rates & stocks on date
    joined = join_on_date(state["evidence"])
    prompt = ("Answer using ONLY this evidence and these computed results.\n"
              f"Evidence: {joined}\nCalculations: {state['calculations']}\n"
              f"Question: {state['question']}\n"
              "Cite [source] tags for every claim. If evidence is insufficient, say INSUFFICIENT.")
    return {"draft": llm.invoke(prompt).content}

Router — CALC vs SEMANTIC vs HYBRID

def route_question(state):
    label = llm.invoke(
        "Classify this question. Reply ONE word:\n"
        "CALC = needs arithmetic on numbers (change, average, correlation)\n"
        "SEMANTIC = asks for meaning, causes, context, description, comparison in words\n"
        "HYBRID = both\n"
        f"Question: {state['question']}").content.strip().upper()
    return {"route": label if label in {"CALC","SEMANTIC","HYBRID"} else "HYBRID"}

Semantic lane — verbalize records, then vector-search them

# AT STARTUP — turn every JSON record into a sentence, so numbers become semantically searchable
from langchain_core.documents import Document
docs = []
for rec in rates:
    docs.append(Document(
        page_content=f"On {rec['date']}, the {rec['series']} was {rec['value']}"
                     f" ({'up' if rec['change']>0 else 'down'} {abs(rec['change'])} from previous).",
        metadata={"source": f"rates.json#{rec['date']}"}))
# if a dataset has real text (news headlines, notes) — index that text directly
vectordb = FAISS.from_documents(docs, embeddings)

def semantic_search(state):
    hits = vectordb.similarity_search(state["question"], k=8)
    ev = [{"source": h.metadata["source"], "record": h.page_content} for h in hits]
    return {"evidence": state["evidence"] + ev}   # same ledger — combine treats both lanes alike
The verbalization trick: pure numeric datasets can't answer "why"-style questions directly — but rendering each row as a sentence ("On 2026-06-03 the cash rate rose 25bp to 4.35%") makes trends and events findable by embedding similarity. Both lanes write to the same tagged evidence[] ledger, so grounding, citations, and confidence work identically for semantic answers. And when the data simply doesn't contain the cause ("why did the RBA hike?" with no news dataset), the honest answer is what the ground-check enforces: describe what the data shows, flag what it can't show, and lower confidence.

Calibrated confidence — computed, not asked

def confidence(state):
    coverage  = datasets_hit(state) / datasets_needed(state["plan"])   # found what we needed?
    citations = cited_fraction(state["draft"], state["evidence"])     # claims backed by sources?
    math_ok   = 1.0 if state["calculations"] else 0.7               # numbers from code?
    score = round(0.5*coverage + 0.35*citations + 0.15*math_ok, 2)
    return {"confidence": score, "abstained": score < 0.4}
Why this wins on "calibrated": most teams ask the LLM "how confident are you?" — models are notoriously overconfident. Computing confidence from measurable signals (dataset coverage, citation rate, whether math came from code) gives scores that actually track accuracy, and you can prove it: bucket benchmark answers by confidence and show accuracy rises with the bucket.

Grounding rules — the system prompt that enforces "supplied data only"

SYSTEM_PROMPT = """You are a market data analyst. Hard rules:
1. Use ONLY the evidence and calculations supplied in the prompt — never your own
   knowledge of markets, rates, or companies. If it's not in the evidence, it doesn't exist.
2. Every claim must cite a [source] tag copied verbatim from the evidence.
3. All numbers must come from the calculations block — never compute or recall numbers yourself.
4. If the evidence cannot answer the question, reply INSUFFICIENT — an honest
   'the data doesn't show this' is a correct answer, not a failure."""
Honest uncertainty, concretely: uncertainty is communicated in three places — the computed confidence score (from coverage/citations/math signals, not the LLM's self-report), the abstained flag when evidence is insufficient, and hedged language in the answer text itself when confidence is mid-range ("the data suggests…" vs "the data shows…"). The ground-check node rejects drafts that state low-coverage claims without hedging.

5 · Beating the benchmark tiers

TierTypical questionPath through the graph
Easy"What was the cash rate on 3 June?"plan → retrieve (1 dataset) → answer. No math, single lookup, confidence high.
Medium"How much did CBA gain in June?"+ calculate: retrieve range, pct_change in code, cite both endpoints.
Hard / cross-dataset"Did bank stocks outperform the rate move after the June decision?"plan splits into 2 sub-queries → retrieve both datasets → calculate per-dataset → combine joins on date → ground-check → answer.
Semantic"How would you characterize rate movements in Q2?" / "Why did stocks fall in June?"route → semantic lane: vector search over verbalized records → combine → answer describes what the data shows, hedges what it can't, confidence reflects coverage.
  • Exact-match safety: put the bare numeric in "value" — graders often string/number-match; don't bury the number in prose.
  • Abstention scores points: on unanswerable questions, "abstained": true with low confidence usually beats a confident hallucination.
  • Run the benchmark early: even 10 questions through the pipeline in hour one exposes format bugs before they cost you the leaderboard.

6 · Self-evaluation harness (run before submitting)

def run_benchmark(agent, questions):
    results = []
    for q in questions:
        out = agent.invoke({"question": q["text"], "retries": 0})
        results.append({
            "id": q["id"],
            "schema_ok": validate_schema(out),
            "citations_real": all(quote_in_source(e) for e in out["evidence"]),
            "reproducible": agent.invoke(...) == out,   # run twice → identical?
            "confidence": out["confidence"],
        })
    return results   # then: accuracy per confidence-bucket = calibration proof
Time budget suggestion: 20% skeleton graph end-to-end with stub nodes → 40% retrieval + calculator on the real JSON → 20% cross-dataset combine → 20% calibration + benchmark runs. A complete simple agent beats an incomplete clever one.
